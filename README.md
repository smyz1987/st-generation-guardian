# Generation Guardian · 生成守护

给 SillyTavern 用的第三方扩展：**回复生成到一半被刷新、被扩展自动更新、被手机系统杀后台打断时，已经吐出来的字不会白白蒸发。**

- 生成中拦截手动刷新 / 关页面（`beforeunload` 确认框）
- 生成中拦住酒馆里那几个**会直接刷新页面**的扩展操作（启用 / 禁用 / 更新 / 删除 / 清理 / 移动 / 换分支）
- 流式生成时把已生成的文字持续写进浏览器本地存储，页面被杀也丢不了
- 刷新回来打开同一聊天，**自动把草稿补回聊天，成为一轮正式回复并保存**（不用点任何按钮），卡片变成「已自动补回」，想反悔有「撤销补回」
- 酒馆被打断后留在聊天里的**半截消息**，也能被草稿补全，不会多出一段重复正文
- 扩展设置区里有一个可折叠面板，开关、指令、保留条数 / 天数、卡住提示都能自己调

---

## 先说清楚它是怎么个省法

被打断的那一瞬间，那次请求的钱**已经花掉了，退不回来**。这个扩展不假装能退款，它做的是：

1. **不让已经付过钱的那部分字蒸发** —— 流式吐出来的每个字都落在本地，刷新、杀后台都还在；
2. **接回不再发请求** —— 点「接回」只是把草稿原样写回聊天，一个字都不重新生成；
3. **要不要继续写，你说了算** —— 点「续写」才会发一条新的请求（等于一次普通对话），你可以不点。

所以省的不是「中断那一次」，而是「不用为了找回半截回复再整条重发一遍」。

### 被打断之后，草稿到底存在哪

这是最容易误会的一点，讲清楚：

| 阶段 | 草稿在哪 | 谁看得到 |
| --- | --- | --- |
| 正在流式输出 | 只在你浏览器的 localStorage（`genGuardian.snapshots.v1`），节流 800ms 落盘 | 聊天里还什么都没有 |
| 页面被杀 / 刷新 / 杀后台之后 | 同上，还躺在本地，刷新都丢不了 | 重载后会把它**写进聊天记录并保存** |
| 补回之后 | 已经成了聊天里的一条正式消息（`chat.json` 里有了） | 酒馆的聊天、存档、导出全都带着它，跟正常生成的一轮一样 |

也就是说：**它不是只给你一段文字，而是真的把那一轮弄回聊天里**，补回时调的是酒馆自己的 `addOneMessage()` + `saveChat()`，还会补齐 `swipe_id / swipes / swipe_info / send_date / force_avatar` 这些字段，所以补回来的消息能正常右滑、能重新生成、能导出。

补回之后你可以直接点酒馆的「继续生成」往下玩；反悔了就在卡片上点「撤销补回」，那条会从聊天里拿掉，草稿退回「已保存草稿」列表（不会丢）。

### 一万五千字的一轮，也是原样留住

长回复最怕两件事：写到一半被截断、或者「保住了」其实只剩头尾。这两件都不会发生：

| 你可能担心的 | 实际 |
| --- | --- |
| 草稿有字数上限吗 | 单条 100 万字以内不截断（`MAX_DRAFT_CHARS`）。**一轮一万两千字只占 24KB**，离上限差两个数量级 |
| 落盘是「追加」还是「整条重写」 | 整条重写，每次都写当前完整累计文本。12000 字 × 每 800ms 一次，也就相当于每秒写十几 KB，浏览器毫无压力 |
| 存不下怎么办 | 全部草稿有 120 万字总预算（≈2.4MB），超了按「最旧先走」，**正在写的这一条永远保留**；真撞到 localStorage 5MB 配额还会逐条驱逐重试 |
| 接回时会不会被截断 | 不会。接回是把 `text` 整段交给 `addOneMessage()`，之后再 `saveChat()`，中间没有任何切片 |
| 会不会「看着完整其实中间被省略」 | 只有超过 100 万字才会插「……（中间过长已省略）……」并把 `truncated` 标在卡片上。12000 字这一档碰不到 |

测试里有一条专门的场景（第 23 个）：一次性喂 15000 字 → 模拟 `beforeunload` 打断 → 重开页面 → 点「接回」，断言**字数相等、内容逐字相等、没有截断标记**。这条一直是绿的。

### 接回的那条，长得跟你正常写出来的一模一样吗

一模一样。接回走的不是「我另画一个文本框」，而是**酒馆自己的渲染函数**：

```
addOneMessage(mes, opts)
  → updateMessageElement(mes, { messageId })
      → getMessageTextHTML(mes, { messageId })
          → messageFormatting(mes.extra?.display_text || mes.mes, mes.name, is_system, is_user, messageId, sanitizerOverrides, false)
              → messageElement.find('.mes_text').html(messageHTML)
```

也就是说 markdown、代码块、自定义 HTML（`<div>` / `<font>` / `<details>`）、正则替换出来的东西、**状态栏那一段 HTML**，全部照原样渲染，跟你平时看到的没区别。`sanitizerOverrides` 只在消息带 `extra.uses_system_ui` 时才放开，我们没写这个字段 —— 所以消毒力度和普通角色消息完全同级。

**唯一的缺口，也是 1.3.7 补上的**：`addOneMessage()` 只画 DOM，**不会** emit `CHARACTER_MESSAGE_RENDERED`（那个事件正常只在 Generate 流程里发）。而状态栏修复、变量、思维链标签、TTS、自动翻译这一大票扩展都挂在这个「这条渲染完了」事件上。不补这一下，就会出现「正文有、状态栏没贴」。

所以接回成功之后会补发一次：

```js
eventSource.emit(events.CHARACTER_MESSAGE_RENDERED, messageId, 'generation-guardian')
```

三个接回路径（接在原来那条后面、补全那条半截的、新加一条）都会发，参数里的 messageId 就是那条消息的真实下标，来源标记写着 `generation-guardian` —— 别的扩展能看出来这不是酒馆主流程发的，想跳过就跳过。不想让它发，面板里关掉「接回后通知状态栏 / 变量类扩展」就行。

### 接回会不会再扣你额度

不会。这一点是断言出来的，不是嘴上说的：

| 动作 | 发给 API 的请求 |
| --- | --- |
| 点「接回」 | **0 条**。只有 `addOneMessage()`（画界面）+ `saveChat()`（存聊天文件） |
| 点「续写」 | **1 条**，就是你那条普通续写指令，跟你平时手打一句话发出去完全一样 |
| 点「只复制指令」 | 0 条 |
| 不管它 | 0 条 |

测试里把 `window.fetch` 换成了计数器，接回完整跑一遍后断言 `chat-completions` 请求数为 0。

一句实话：如果你开着**自动翻译**或 **TTS** 扩展，补发那个渲染事件之后它们可能会跟着响应一次 —— 那是它们本来在每次正常生成后都会做的事，不是本扩展额外加的请求。真要一点旁支动静都不要，把上面那个开关关掉，代价是状态栏可能不贴。

### 它拦不住的打断（照样会断，但字不会丢）

能做的和做不到的分开写，免得误以为它是万能的：

| 打断方式 | 能拦吗 | 结果 |
| --- | --- | --- |
| 在酒馆里点扩展的启用 / 禁用 / 更新 / 删除 / 清理 | 能，就地拦下并提示 | 回复继续写，不用重发 |
| 手动按 F5 / 点浏览器刷新 / Ctrl+R | 弹确认框（Chrome、Edge、Firefox 桌面端有效） | 你点取消就不断 |
| 手机浏览器下拉刷新 / 手机系统杀后台 / 锁屏被回收 | **拦不住** | 生成会断，草稿在本地，回来打开同一聊天会自动补回聊天并落盘 |
| 网络断开、代理掉线、API 超时、上游 429 | **拦不住** | 同上 |
| 生成中切换聊天 / 换角色卡 / 编辑或删除消息 | **拦不住**（酒馆自己会中止） | 同上，回到原聊天会弹卡片 |
| `/reload` 斜杠命令、切换界面语言、重置用户配置 | **拦不住**（命令和别处代码直接调 reload） | 同上 |
| 浏览器崩溃、断电、手滑关掉标签 | **拦不住** | 草稿最多丢最后 0.8 秒的字 |

**「刷新后在后台继续输出」物理上做不到**：生成是浏览器这条连接在收流，页面一断，上游连接就断了，前端不可能替它续上。所以这里做的是「断了不丢、想要就自己接着要」。

## 为什么不用酒馆原生的 continue

酒馆的 `continue` 是把最后一条消息当 assistant prefill 硬接着往下吐，两个毛病：

- 模型容易接不上、复读、语气漂移，越写越崩；
- 它会 append 回同一条消息里，等于为已经写过的半截再付一次上下文。

所以这里换成**一条普通指令**：由扩展替你发一条「续写」指令，模型重开一段正文。质量稳定得多，也便宜。

（「继续生成」被打断的情况例外：那种本来就是在同一条消息上续，草稿会拼回那条消息，不算新请求。）

## 安装

### 方式一：从 GitHub 直装（PC + 手机通用）

打开 SillyTavern → 顶部「扩展 / Extensions」→ `Install Extension` → 地址填：

```
https://github.com/smyz1987/st-generation-guardian
```

安装后刷新页面，扩展列表里能看到 **Generation Guardian (生成守护)** 就是装好了。

扩展装在**服务端目录**里，所以只要是同一个 SillyTavern 实例，手机浏览器访问同一个地址就自动有，手机端不用单独装。

### 方式二：手动放进目录

把整个仓库文件夹放到：

```
SillyTavern/public/scripts/extensions/third-party/gen-guardian/
```

目录名随意，只要里面有 `manifest.json`、`index.js`、`style.css`。放好刷新页面。

### 方式三：手机 Termux 自建

```bash
cd SillyTavern/public/scripts/extensions/third-party
git clone https://github.com/smyz1987/st-generation-guardian gen-guardian
```

手机浏览器刷新即可。

## 怎么用

生成被打断（刷新回来、或者连接断掉）后，屏幕下方弹出卡片，五个按钮：

| 按钮 | 干什么 | 花不花额度 |
| --- | --- | --- |
| **接回** | 把草稿原样写回聊天，成为一条正式消息；如果酒馆留了半截消息，就补全那一条。**新版默认自动帮你做这件事，不用点这个按钮** | 不花 |
| **续写** | 先接回，再把那条续写指令放进输入框，光标停在末尾等你补两句；只有你勾了「直接发送」它才替你按发送 | 只填不发时只有你按下发送才花额度 |
| **复制指令** | 只把续写指令复制到剪贴板，你自己发 | 不花 |
| **放入输入框** | 把草稿文字塞进输入框，自己改完再发 | 不花 |
| **丢弃** | 删掉这条草稿 | 不花 |

「换一条 / swipe」和「替我说话 / impersonate」这两类生成没法续写，卡片会把「接回」「续写」藏起来，只让你放进输入框或复制。

### 续写指令长什么样

默认两条预设，设置面板里点一下就能换，也可以自己改：

**主线**

```
继续生成上一轮剧情，衔接上文末尾，不要从头开始。不复述、不重复已经写过的内容，保持原有的视角、人称、语气和文风，直接从正文往下写。
```

**番外**

```
继续生成上一个番外，衔接上文末尾，不要从头开始。不复述、不重复已经写过的内容，保持原有的视角、人称、语气和文风，直接从正文往下写。
```

点「续写」时，这条指令会作为**你的一条消息**发进聊天（模型得看得见它），所以聊天记录里会多一条你的话。不喜欢就手动删掉那条。

| 被打断时自动补回聊天 | 默认开。生成断了就把草稿直接写回聊天并保存，成为一轮回复；关掉就退回手动点「接回」 |
| **安静模式** | 默认开。正常写完一句话都不吭 —— 不弹卡片、不弹 toast、不提示「好像卡住了」。只有**真的被打断**（刷了页 / 被别的扩展 stop 掉）才出声 |
| 拦住扩展管理请求 | 默认开。生成中拦住扩展的自动更新 / 安装 / 删除请求（它们做完会刷新页面）。拦不住的时候，刷新回来也会自动补回 |
| 拦截扩展操作时想强行通过 | 生成中按住 **Shift** 点那个扩展按钮，这一次就放行（草稿会先落盘） |
| 最多保留 / 保留天数 | 草稿最多存几条、存几天，超了自动淘汰最旧的 |
| 卡住提示 | 多少秒没有新字就先把草稿钉死并提示，填 0 关掉（安静模式下这一条不会弹） |
| 已保存草稿 | 草稿清单，可单条复制 / 删除，也可全部清空 |

默认**没有任何倒计时、没有任何自动续写**——不会在你不知情的时候自己发请求。

### 「安静模式」是怎么个安静法

原来的版本有两处会多嘴：① 酒馆把消息塞进 `ctx.chat` 常常比 `GENERATION_ENDED` 晚半拍，代码一看到「还没落地」就弹「生成结束时内容没写进聊天」，其实人家马上就写进去了；② 45 秒没新字就弹「好像卡住了」，可模型思考久一点、写长段落本来就会静很久。

现在：

- 正常收尾（`ended`）的草稿打上 `endedCleanly` 标记，**隔 1.2s / 1.5s / 2s / 3s 复核四次**，只要中途发现已经写进聊天就把草稿删掉，一声不响。
- 四次复核完还是没落地 → 草稿留作「备份」（面板里那行会写「备份 · 这一轮已正常写完」），**不弹卡片、不弹提示**，而且它**永远不会**在刷新后被当成「未完成的回复」弹出来。
- 卡住提示在安静模式下也不弹（只是内部继续盯着）。
- 真被打断（`stopped` / 刷新 / 手机杀后台）照旧：该保住就保住、该补回就补回、该吭一声就吭一声。

### 八套主题

配色不是我随手挑的：八组色号逐字取自「网页配色逻辑」那八张配色卡，一个值都没改过。
每张卡只给两支色——一个极浅的中性底，一个中低饱和的彩色中间调。面板上所有角色都由这两支按**同一组比例**混出来，
所以八套是同一副骨架换皮，不是八套各写一遍再各调一遍。

| # | 主题 | 底色（大面积） | 彩色中间调（结构与字） | 彩块上的字 |
| --- | --- | --- | --- | --- |
| 01 | **杏仁白** Almond（默认） | `#F3E8DC` | `#A37070` 雾玫瑰 | `#FFFDF8` |
| 02 | **暖奶油** Cream | `#FDF4E3` | `#7C8D99` 迷雾蓝 | `#232A30` |
| 03 | **雾蓝灰** Blue Haze | `#E1E6E9` | `#A35E5E` 红陶土 | `#FFFDF8` |
| 04 | **桃奶茶** Peach Tea | `#F6E3D7` | `#A3A88F` 鼠尾草绿 | `#33352A` |
| 05 | **白茶灰** White Tea | `#EFECE6` | `#9E6C55` 琥珀褐 | `#FFFDF8` |
| 06 | **南瓜米** Pumpkin | `#F5E2C3` | `#7DA8B1` 海盐蓝 | `#23343A` |
| 07 | **奶油绿** Butter | `#EDF0E2` | `#B48A78` 裸玫瑰粉 | `#3B2C25` |
| 08 | **莲子白** Lotus | `#F5F2EE` | `#A9A1B0` 浅藤紫 | `#37333C` |

分配只有一条规则：**浅的那支铺大面积，彩的那支只管结构和字**。

- **浅色永远是底**。`--gg-bg` 直接用底色，面板本身是「底色混 30% 白」——全站最亮的一层，浮在底色上；输入框、按钮底是「底色混 62% 白」，压在中间。三层的明度差就是层次，不靠阴影堆。
- **彩色只出现在五处**：抽屉标题条、八张主题色卡、主按钮、开关打开态、分区编号（01–06 的小方块）。全是结构件，不落在任何一条设置行上——设置行只用一条 1px 分隔线和一个悬停底色，绝不出现独立彩色背景块。
- **彩色面积压在三成左右**。剩下的七成是底色和接近白的面板，所以八套都不会变成「深色铺满、浅色当字」。
- **文字永远在浅底上**。正文色是「彩色混 38% 近黑」，深到对面板 ≥ 7:1；次要文字混 54%，弱提示混 68%。彩色本身只做色相来源，不让它直接承担小字。
- **彩块上的字按彩色的亮度定**，就是表里最后一列：八套彩色偏深的配浅字（`#FFFDF8`），另另四套偏亮的配深字（各配一支同色系的深墨），最低一组也到 4.3:1，枫叶大的 11.5px 字也读得清。
- **强调色稀缺**。「彩色只做结构」本身就是最大的克制：一屏里彩色加起来不到三分之一，没有一处是用来「填满」的。

**面板本身的装饰**，1.3.10 这一轮收成了这样：

| 部位 | 现在 |
| --- | --- |
| 抽屉标题条 | 彩色中间调实底，字用该套定死的 ink，左上 1px 高光，圆角 10——整块面板的「色彩身份证」就在这一条上 |

**关于液态玻璃，做到了哪一步、没做到哪一步**（那份方案 6 页读完了）：

- 方案的核心结论是「CSS 定义形，WebGL 定义光」——真正的折射是 WebGL 拿场景颜色重新算出来的，纯 CSS 的 `backdrop-filter` 只有模糊和调色，没有位移。所以**没做的那一步是折射**，任何声称「纯 CSS 折射」的都是假的。
- 做得到、也已经落地的五条：① 背景真透（中心厚边缘薄，`backdrop-filter` 32px/1.6/1.08）；② 方向性边缘光（上/左右亮边、下沿暗边，不是一圈均匀描边）；③ 一圈亮度有方向的渐变细边框，并夹了两丝冷/暖色当色散；④ 板身斜向反光带 + 左上高光点，26 秒极慢横移（`prefers-reduced-motion` 下自动停）；⑤ 双层投影（1px 接触影 + 大范围环境影）。
- 代价写在明处：**面板不再是一块实的白纸**，底色会渗进来一点点。真机上酒馆背景如果是深色，面板会比浅色主题下稍微沉一点，`brightness(1.08)` 是给这个准备的补偿。


- 切换在设置面板第一节「主题」，八个按钮，`aria-pressed` 标记当前项，点一下就换，`body` 上挂 `gg-theme-<key>`。
- 换主题只改我自己这四块（徽标 / 恢复卡片 / 设置抽屉 / 按钮）的配色，**不动酒馆自身的主题设置**，也不改任何字体。
- 旧存档里的 `trianon` / `dusk` / `neon` / `frost` 会自动回落成默认的 `almond`（`themeKey()` 只认 `THEMES` 里有的键），不会报错也不会白屏。


### 字体

**控件字体全部 `font-family: inherit`，跟随酒馆的全局字体**（你在酒馆里开的「跟随全局字体」会直接作用到面板上）。扩展自己只加了两样很轻的东西：标题的 `letter-spacing`、以及主题色，不覆盖任何字体设置。装在手机上也不会拿系统字体顶替。

### 界面

装好以后，酒馆顶部「扩展 / Extensions」的设置区里会多出一个**可折叠的条目**（`Generation Guardian · 生成守护`），点标题展开/收起，里面分「主题 / 开关 / 续写指令 / 存储 / 已保存草稿」五节，所有参数都在这里调。

装饰细节：外层细线框 + 顶部细密缆线纹 + 内层第二条细框（双框）、章节标题左右对称的引线、金色菱形分隔、恢复卡片四角的 L 形角线、主按钮的金属渐变、状态徽标上呼吸的圆点。

## 强烈建议顺手做的两件事

1. **必须开流式输出**（`Chat Completion → Streaming`）。不开就没有中间内容可存，这扩展基本没用。
2. **别让别的扩展自动更新打断你。** 第三方扩展 manifest 里写 `"auto_update": true` 的，酒馆会定期检查并更新，更新流程可能触发页面重载。可以：
   - 把用不上的扩展的 `auto_update` 改成 `false`；
   - 或看 `config.yaml` 里的 `extensions.auto_update`。

   本扩展自己是 `"auto_update": false`，不会更新自己把你正在生成的回复刷掉。

## 技术实现（给想改的人）

| 环节 | 做法 |
| --- | --- |
| 开始记录 | `GENERATION_STARTED`，记下 `chatId`、聊天长度、锚点消息指纹（FNV-1a hash + 前 60 字） |
| 兜底记录 | 万一没收到开始事件，收到第一个 token 时用当前聊天状态现场补一个骨架 |
| 保存内容 | `STREAM_TOKEN_RECEIVED` 给的是**当前累计的原始文本**，直接覆盖写入，节流 800ms 落盘 |
| 强制落盘 | `pagehide` / `visibilitychange=hidden` 时同步写一次（手机被冻结前抢一次） |
| 卡死兜底 | 45 秒没有新 token 也没结束事件，先把草稿钉死并提示「好像卡住了」 |

| 恢复校验 | 聊天长度 + 锚点指纹双重校验，避免串到别的聊天或你后来又发了新消息的情况 |
| 半截补全 | 聊天最后多出一条「草稿的前缀」，判定为被打断的那条，接回时直接补全而不是新增 |
| 接回 | `chat.push()` + `addOneMessage()` + `saveChat()`，不调用生成；失败时回滚已插入的消息 |
| 自动补回 | 重载 / 打断后 `scan` 到可恢复草稿就自动走一遍接回（默认开，可关），成功后卡片切「已自动补回」并记住那条的 index 供撤销 |
| 续写 | 写进 `#send_textarea` 再 `generate('normal')`，等价你手打发送；失败时把指令填回输入框 |
| 拦截刷新 | `beforeunload` + 捕获阶段拦两类会刷新的点击：① `.extensions_info` 里真会 `location.reload()` 的 4 类按钮（启用 / 禁用 / 删除 / 清理）；② 别的扩展「发现新版本」弹窗里的「更新」按钮（点完它自己 1 秒就刷）。按住 Shift 点 = 这一次放行（先落盘再让它去刷） |
| 不拦什么 | 「更新 / 换分支 / 移动」只改文件、酒馆源码里也不 reload，所以一概放行 —— 点更新不会变成「点了没反应」 |
| 存储兜底 | localStorage 写满时逐条驱逐旧草稿，保证当前这条一定写得进去 |
| 幂等 | 恢复中加锁 + 二次校验草稿是否还存在，双击按钮不会插两条消息 |
| 界面 | `extensions_settings2` 里挂一个 ST 标准的 `.inline-drawer`（官方点击折叠逻辑自动接管）；内含「兼容状态」一栏，实时列出检测到的会主动刷新的扩展以及各自怎么处理；八套主题是 `body.gg-theme-*` 上的 CSS 变量，字体全部 `inherit` |
| 调试 | 控制台 `GenerationGuardian.snapshots()` / `.liveDraft()` / `.scan()` / `.clear()` |

### 1.3.11 这一步修掉的东西（对着 1.19.0 源码逐条核过）

| 原来会怎样 | 现在怎么判 |
| --- | --- |
| 「换一条」被打断后，即使那条已经完整写进聊天，草稿永远判不成「已落地」—— 每次刷新都弹一张「检测到未完成的回复」 | 补了换一条的落地判定：消息总数不变时，去比对那条消息的 `mes` 和整个 `swipes` 数组，命中就清草稿 |

### 1.3.14：面板不再「一大串东西拖着」，六块全折成六行

她的原话是「那么长一串东西拖着像什么样子」。一个设置页摊开十几行，找什么都得先滚。

现在打开面板先看到的是六行标题，一行一块：

```text
[01] 主题        ●●●●●●●●  杏仁白      ⌄
[02] 开关                                 ⌃   ← 只有这块默认开着
[03] 续写指令                             ⌄
[04] 存储                                 ⌄
[05] 兼容状态   8                         ⌄
[06] 已保存草稿 0                         ⌄
```

- 展开的高度用 `grid-template-rows: 0fr → 1fr` 算出来，不写死 `max-height`，摊开多少就多高，没有半截裁断。
- **主题那一条的小巧思**：收起时它是一块**完整的深色圆角托盘**，摊开时只留上面两个角、下面接八张浅卡 —— 盖子掀开那一下。右边那排八颗点就是八套配色本身，横着排成一条调色盘；当前那套的点大一号、外面套一圈同色环，不展开也知道现在是哪一套。
- 八张卡摊开时从左到右依次浮上来（`--gg-i` 做阶梯延迟），`prefers-reduced-motion` 下关掉。
- 兼容状态、已保存草稿的条数挂在**收起的标题行**上（一枚小徽章），不用摊开也数得清。
- 「◆」那种分隔符和 `.gg-sub` 平铺小标题整套删了，序号由标题行自己的 `01`–`06` 承担。

### 1.3.14：按钮不再扛着解释，解释搬进一次性引导

她原话：「面板里的按钮不要这么多解释性语言，你几句话放按钮不觉得很累赘吗。你加个新手引导就行了，一步步带着解释。」

八个开关的名字全砍短：

| 原来 | 现在 |

| 生成中拦截刷新 / 关闭页面 | 拦截刷新和关闭页面 |
| 生成中拦住会刷新的扩展操作（启用 / 禁用 / 删除 / 清理；更新和换分支不拦） | 拦住会刷新的扩展操作 |
| 被打断时自动补回聊天（不用点「接回」） | 被打断时自动接回 |
| 安静模式：正常生成完什么都不弹，只有真被打断才出声 | 安静模式 |
| 接回后通知状态栏 / 变量类扩展「这条渲染好了」（本扩展不额外发请求） | 通知状态栏类扩展 |

三个 `.gg-hint` 说明段整段删掉，「秒没新字就提示（0 关掉）」改「秒没字就提示」。面板上再没有一整句解释。

换来的是一份 **7 步新手引导**（`GUIDE_STEPS`）：

1. 它管什么（痛点：写一半被刷新，字没了、额度白花）
2. 主题（八颗点就是八套，盖子掀开）
3. 两个拦截
4. 接回的两个开关
5. 通知和入口
6. 续写和存储
7. 兼容状态和草稿 + 入口在哪

- **第一次用自动弹一遍**（`guideSeen` 默认 `false`，`initOnce` 后 900ms 弹）；关掉就写 `guideSeen = true`，之后再也不主动弹。
- 想重看：面板最下面那行版本号右边多了一枚小「?」（`#gg-help`），点它从第 1 步重来。
- 引导是浮在 `body` 上的一层薄雾 + 一张卡，`z-index` 拉到最高；点遮罩空白处、点 ✕、走完最后一步点「开始用」都能关。手机端卡片贴底、宽度拉满。

### 1.3.14：入口再从 QR 栏挪出来，放回酒馆自己的魔法棒

1.3.13 把入口塞进了 QR 快捷栏（`#qr--bar`）。她试下来仍然看不到，然后直接定了方向：「不用了。你别做酒馆助手脚本，你把扩展快捷放魔法棒里。」

原因说清：QR 栏那套靠 `quickReplyV2.isEnabled`，她的 `settings.json` 里那就是 `false`；而「qr 助手」的折叠栏里装的是酒馆助手（JS-Slash-Runner）的**脚本按钮**，扩展没法把自己的东西塞进别人的按钮栏。两条路都不稳 —— 那就走第三条：**酒馆自己的魔杖菜单**。

现在的做法（`mountWandEntry`）：

- 目标容器 `#extensionsMenu`，由 `scripts/extensions.js:688` 的 `addExtensionsButtonAndMenu()` 在启动后建出来（`renderTemplateAsync('wandMenu')`），所以挂不上就每 400ms 重试，最多 10 次。
- 结构照酒馆原生模板：`#extensionsMenu > .extension_container > div`。我们自己建一个 `#gg_wand_container.extension_container`，里面放一条 `#gg-wand-entry`。
- **不另造一套皮肤**：底色、hover、圆角、内边距全部交给酒馆自己的 `#extensionsMenu > .extension_container > div` 规则；CSS 只补排版和生成中那行小字。任何全局美化下它跟别的扩展按钮长得一样。
- 一条里三样东西：`fa-shield-halved extensionsMenuExtensionButton` 图标位（跟原生扩展按钮同款）、`生成守护` 四个字、右边一行小字 —— 平时空着，生成中报「已保存 N 字」。
- 点它 → `openSettingsDrawer()`：先点开「扩展」那条抽屉（`#extensions_settings2` 的 `.drawer-content.closedDrawer` 找 `drawer-toggle` 点一下），再摊开本扩展的 `.inline-drawer-content`，滚到面板。顺手把魔杖菜单收起来（`closeWandMenu()`）。
- 「魔杖菜单留一条入口」这个开关（原 `showBadge`）关掉就整条 `display:none`，不占别人的位置。
- **`#qr--bar` 那一整套全删了**：`quickBarHost` / `syncBadge` / `watchQuickBar` 和对应的 CSS、移动端那条规则，连 `#gg-badge` 这个 id 都不存在了。
- `MutationObserver` 也不再需要，测试里的 `defineGlobal('MutationObserver')` 一起撤掉。

### 1.3.13：生成结束那一瞬间，也不许刷新溜进去

这是「我有阴影了」那条。以前只拦「正在生成中」，但真正丢字最狠的一段其实在**刚刚写完**那一刻。

酒馆的流式机制（`script.js`，1.19.0）：

1. `onStartStreaming` 开流时先 `await saveReply(...)`，落一条**空消息**；
2. 中途 `onProgressStreaming` 只改内存里的 `chat[messageId].mes`，**一个字都不写盘**；
3. `hideStopButton()` 里同步 `eventSource.emit(GENERATION_ENDED, ...)`；
4. 真正的 `saveChat` 排在这一串之后。

也就是说「生成结束」这个事件发出的那一瞬，磁盘上还是空的。老代码在 `onGenerationFinished` 第一行就把 `unloadGuard` 解掉了 —— 这段窗口完全敞开，别家扩展 0.5～3 秒刷一下，屏幕上刚写完的整段当场消失，额度白花。

现在：

- 结束不立即解除，进 **12 秒落盘保护窗口**（`POST_GEN_GUARD_MS`）；
- 只要确认「字已经进聊天了」（`chatDraftLanded` 命中，含 swipe 情形）就**提前收手**，不多缠一秒；
- 拦截文案分两种：生成中 →「正在生成中，刷新会中断回复」，刚写完 →「这段回复刚写完、正在存进聊天，现在刷新可能整段丢」；
- 两处点击拦截（禁用/删除扩展、扩展弹窗里的「更新」）也改判这个条件，同样分文案。

### 1.3.13：入口挪进 QR 快捷栏，并跟着酒馆的全局美化走

- **聊天框上方不再挂任何东西**。原来那个 `position: fixed` 的徽标撤了，改成往 QR 快捷栏（`#qr--bar`，或酒馆助手建的那条）里 append 一条；结构照酒馆助手 `use_button_destination_element.ts` 的写法：`quickReplyV2.isCombined` 时进 `.qr--buttons`，否则进 `#qr--bar` 本身。

- 平时那条就是「生成守护」四个字，生成中借它报「已保存 N 字 · 别刷新」，点它跳到扩展页并展开抽屉。

- 扩展页里那一行的样式**改成和酒馆原生 `.inline-drawer-header` 完全一致**（透明底、无圆角、无阴影、`padding: 5px 0`、字号字色 `inherit`），只留一个 5px 的主题色小方点做识别。之前它是一条深色圆角药丸，任何全局美化下一换，它就是列表里最扎眼的那块。

### 1.3.12：续写默认只填不发

「续写」原来是点一下就把指令发出去。实际用下来常常不是想要的 —— 你想在指令后面补一句「这次写打斗」「换个视角」，结果请求已经飞出去了，只能等它写完再重来。

现在默认改成**只填不发**：

- 指令写进输入框，**光标停在末尾**，接着往下打就行
- 一个字都不发，额度完全不动
- 真想让它直接发，去设置里勾上「点「续写」后直接替我发出去」

「接回并续写」按钮同理：接回照样自动补回聊天，但指令只放到输入框，提示文案也跟着改成「补完按发送」，不再谎称「正在发」。

### 为什么它不会影响你正常聊天

这是这一版专门加固的地方，逐条对着「可能出问题的地方」来的：

| 风险 | 处理 |
| --- | --- |
| 生成完了，扩展还在拦扩展按钮 / 还在拦刷新 | 「生成中」不只看一个 flag，还要看在 5 分钟内确实有新字进来；没有就当场 `releaseGeneration()` 解锁，连徽标一起收掉 |
| 结束事件丢了，状态永远卡在「生成中」 | 卡住看门狗到点后复核，超过 5 分钟直接收尾，草稿留着，状态放开 |
| 我自己的回调抛异常，把酒馆的事件链炸了 | 五个事件回调全部包在 try/catch 里，出错只打一条 `console.warn`，事件照常传给后面的监听者 |
| 点别的地方被误拦 | 捕获阶段的监听只认 `.extensions_info .extension_block` 下那 4 类选择器，加上「弹窗里 + 写着自动刷新 + 文字是更新」的按钮；其余点击一律原样放行（不 `stopPropagation`、不 `preventDefault`） |
| 和别的扩展打架 | **一个全局函数都不包装**：不碰 `fetch`、不碰 `addOneMessage` / `saveChat` / `generate`、不改 `location`，只用公开的 `getContext()` 读数据 |
| 挡住正常聊天请求 | 根本不参与请求层，`/api/backends/chat-completions/generate` 这类正事请求完全不受影响（测试里专门断言 `window.fetch` 没被换掉） |
| 样式串味 | 颜色和字体只在 `#gg-badge` / `#gg-panel` / `#gg-settings` 里生效，`body` 上只加 `gg-theme-*` 四个 class，不碰 `.mes`、`.chat` 这些酒馆自己的类 |
| 不停写盘拖慢聊天 | 落 localStorage 动态节流：草稿 2 万字符以内 300ms 一次，超过就退回 800ms；DOM 只在字数或状态变化时更新；面板隐藏时不重建列表 |
| 动到你的聊天数据 | 只会插入「被打断的那一条」，也就是它本该在的位置；撤销按钮可以拿掉。别的时候只读，不删消息、不改角色卡、不改酒馆任何文件 |
| 两个标签页 / 扩展被重复加载 | 扫描加了一把 3 秒的跨实例锁，「撤销补回」需要的记录写在面板 `dataset` 上而不是只放变量里 —— 另一个实例点撤销也能拿到同一份记录 |
| 联网 / 隐私 | 组装层面零外部请求，草稿只存在你浏览器的 localStorage 里（key `genGuardian.snapshots.v1`） |

真出问题要立刻停手：设置面板关掉「启用插件」，或者在控制台敲 `GenerationGuardian.settings().enabled = false`。

关键文件：

```
manifest.json   扩展清单（auto_update: false）
index.js        全部逻辑
style.css       样式，含手机端断点
tests/          本地测试沙盒
```

## 已知限制

- 关闭流式输出时没有中间内容可存。
- 打断那一次请求的钱回不来，本扩展只保住已经生成的文字。
- 「换一条 / swipe」「替我说话 / impersonate」无法续写，只能进输入框。
- 草稿存在本机浏览器 localStorage：PC 和手机不互通，换浏览器 / 清缓存会丢，内容为明文。
- 手机端部分浏览器（尤其 iOS Safari）对生成中的刷新确认框支持不佳，可能不弹窗直接刷新 —— 靠草稿恢复兜住。
- 单条草稿超过 100 万字会截断保留头尾，卡片上会标「过长已截断」。
- 依赖 `STREAM_TOKEN_RECEIVED` 事件，低于 1.12 的旧版本可能没有。
- 同一浏览器开两个酒馆标签同时生成，两条草稿可能互相覆盖（同时只会有一个标签在生成）。
- **浏览器不允许改写 `location.reload`**（HTML 规范里 Location 的属性是 Unforgeable），所以「把刷新延后」这件事做不到。能拦的是「发起刷新的那一跳」：那 4 类 UI 按钮 + 别的扩展更新弹窗里的「更新」。如果某个扩展是自己直接调 `location.reload()`（本机至少 10 个扩展会这样），页面照样会刷 —— 这时候靠的是草稿已落盘（`beforeunload` 那一刻强制再写一次）+ 回来自动补回。
- 生成中按下那 4 类按钮、以及扩展更新弹窗的「更新」会被拦；扩展管理面板里的「更新 / 换分支 / 移动」不拦（它们不会 reload），所以**不会**让扩展更新变成「点了没反应」。

## 和本机装着的扩展的关系

本机装在两处：`public/scripts/extensions/third-party`（7 个）和 `data/default-user/extensions`（41 个）。

### 不刷新、但需要知道它们存在的

- **包装了 `window.fetch`**：Horae / JS-Slash-Runner / Luker / SillyTavern-AvatarDeblur / ST-Character-Manager / kimi / story-oracle / claude-web。**本扩展一个全局函数都不包装**（不碰 `fetch` / `addOneMessage` / `saveChat` / `generate` / `location`），只用公开的 `getContext()` —— 这是能跟它们共存的前提。
- **会自己调 `stopGeneration()`**：kimi（流式中截断思维链）、Horae、JS-Slash-Runner、story-oracle、st-first-message、gaga-world-forge、st-theater、Luker。被它们停下来的走 `GENERATION_STOPPED` 分支，草稿留住、不重复插入。
- **纯 UI**：Extension-TopInfoBar / SillyTavern-Timelines / Extension-Silence / SillyTavern-Layout / statusbar-fixer / SillyTavern-AvatarCropper / theme-manager / PersonaGroups 等，不刷新也不包装全局，无冲突。

### 生成中会拦下的「更新」按钮

柏宝箱这一类扩展的「发现新版本」弹窗，点「更新」后它自己 `setTimeout` 刷新 —— 那是别人家的定时器，事后取消不了，**唯一能在还没刷的那一刻做点什么的办法就是拦这次点击**。

判定收得很紧，同时满足才拦：① 按钮文字是「更新 / 立即更新 / 现在更新」这类；② 它所在弹窗里出现了「自动刷新页面」字样；③ 不在酒馆扩展管理面板里（那里的 `.btn_update` 只 toast、不 reload，点它安全）。按住 **Shift** 点 = 放行（先把草稿落盘，再让它刷）。

### 一个真机上才发现的问题：`loading_order` 不能给 100

第一版 `manifest.json` 写的是 `loading_order: 100`。真机干净重载后扩展**根本没被加载**（`window.GenerationGuardian` 是 `undefined`，面板也不出现），但 `/api/extensions/discover` 能列出它、手动 `import()` 也成功。

原因：酒馆 `extensions.js` 的 `activateExtensions()` 是**按 `loading_order` 升序、在 for 循环里 `await` 每个扩展的激活**。本机一堆扩展都是 `100`（claude-web / TopInfoBar / JS-Slash-Runner / Horae / story-oracle / st-theater …），排在 `100` 末尾的很容易被前面某个卡住的扩展连累，永远轮不到。

改成 `loading_order: 5` 之后，干净重载能稳定自动加载。同时 `mountSettings()` 加了「面板容器还没渲染就隔 300ms 重试，最多 12 次」—— 因为加载得早时 `#extensions_settings2` 可能还没出来。

一句话：**刷新这件事在浏览器层面拦不住，所以本扩展的做法是「别拦，抢在刷新前存好」** —— 所有导航（`reload` / `replace` / 关页 / 手机杀后台）之前浏览器必定触发 `beforeunload`，我们在那一刻把草稿刷成最新；回来自动补回成正式一轮。
