# Generation Guardian · 生成守护

给 SillyTavern 用的第三方扩展：**回复生成到一半被刷新、被扩展自动更新、被手机系统杀后台打断时，已经吐出来的字不会白白蒸发。**

- 生成中拦截手动刷新 / 关页面（`beforeunload` 确认框）
- 生成中拦住酒馆里那几个**会直接刷新页面**的扩展操作（启用 / 禁用 / 更新 / 删除 / 换分支）
- 流式生成时把已生成的文字持续写进浏览器本地存储，页面被杀也丢不了
- 刷新回来打开同一聊天，弹出恢复卡片：**「接回」把草稿原样写回聊天，「续写」替你发一条续写指令**

---

## 先说清楚它是怎么个省法

被打断的那一瞬间，那次请求的钱**已经花掉了，退不回来**。这个扩展不假装能退款，它做的是：

1. **不让已经付过钱的那部分字蒸发** —— 流式吐出来的每个字都落在本地，刷新、杀后台都还在；
2. **接回不再发请求** —— 点「接回」只是把草稿原样写回聊天，一个字都不重新生成；
3. **要不要继续写，你说了算** —— 点「续写」才会发一条新的请求（等于一次普通对话），你可以不点。

所以省的不是「中断那一次」，而是「不用为了找回半截回复再整条重发一遍」。

---

## 为什么不用酒馆原生的 continue

酒馆的 `continue` 是把最后一条消息当 assistant prefill 硬接着往下吐，两个毛病：

- 模型容易接不上、复读、语气漂移，越写越崩；
- 它会 append 回同一条消息里，等于为已经写过的半截再付一次上下文。

所以这里换成**一条普通指令**：由扩展替你发一条「续写」指令，模型重开一段正文。质量稳定得多，也便宜。

## 安装

### 方式一：从 GitHub 直装（PC + 手机通用）

1. 把本仓库推到 GitHub（见下方「发布到 GitHub」）。
2. 打开 SillyTavern → 顶部「扩展 / Extensions」→ `Install Extension`。
3. 地址填 `https://github.com/<你的用户名>/st-generation-guardian`，点安装。
4. 刷新页面，扩展列表里能看到 **Generation Guardian (生成守护)** 就是装好了。

扩展装在**服务端目录**里，所以只要是同一个 SillyTavern 实例，手机浏览器访问同一个地址就自动有，手机端不用单独装。

### 方式二：手动放进目录

把整个仓库文件夹放到：

```
SillyTavern/public/scripts/extensions/third-party/gen-guardian/
```

目录名随意，只要里面有 `manifest.json`、`index.js`、`style.css`。放好刷新页面。

### 方式三：手机 Termux 自建

如果酒馆跑在 Termux 里，`cd` 到 `public/scripts/extensions/third-party`，然后：

```bash
git clone https://github.com/<你的用户名>/st-generation-guardian gen-guardian
```

手机浏览器刷新即可。

## 怎么用

生成被打断（刷新回来、或者连接断掉）后，屏幕下方弹出卡片，五个按钮：

| 按钮 | 干什么 | 花不花额度 |
| --- | --- | --- |
| **接回** | 把草稿原样写回聊天，成为一条正式消息 | 不花 |
| **续写** | 先接回，再替你发一条续写指令，让模型接着往下写 | 多一次普通请求 |
| **复制指令** | 只把续写指令复制到剪贴板，你自己发 | 不花 |
| **放入输入框** | 把草稿文字塞进输入框，自己改完再发 | 不花 |
| **丢弃** | 删掉这条草稿 | 不花 |

「换一条 / swipe」和「替我说话 / impersonate」这两类生成没法续写，卡片会把「接回」「续写」藏起来，只让你放进输入框或复制。

### 续写指令长什么样

默认两条预设，设置面板里点一下就能换，也可以自己改：

**剧情**

```
继续生成上一轮剧情，衔接上文末尾，不要从头开始。不复述、不重复已经写过的内容，保持原有的视角、人称、语气和文风，直接从正文往下写。
```

**番外**

```
继续生成上一个番外，衔接上文末尾，不要从头开始。不复述、不重复已经写过的内容，保持原有的视角、人称、语气和文风，直接从正文往下写。
```

点「续写」时，这条指令会作为**你的一条消息**发进聊天（模型得看得见它），所以聊天记录里会多一条你的话。不喜欢就手动删掉那条。

## 设置

扩展设置区里有：

| 项 | 说明 |
| --- | --- |
| 启用插件 | 总开关 |
| 生成中拦截刷新 / 关闭页面 | 同时管着「拦住会刷新的扩展操作」 |
| 续写指令 | 点「续写」时发的那条文字，可编辑；旁边两个按钮一键换成剧情 / 番外预设 |
| 已保存草稿 | 草稿清单，可单条复制 / 删除，也可全部清空 |

默认**没有任何倒计时、没有任何自动续写**——不会在你不知情的时候自己发请求。

---

## 强烈建议顺手做的两件事

1. **必须开流式输出**（`Chat Completion → Streaming`）。不开就没有中间内容可存，这扩展基本没用。
2. **别让别的扩展自动更新打断你。** 第三方扩展 manifest 里写 `"auto_update": true` 的，酒馆会定期检查并更新，更新流程可能触发页面重载。可以：
   - 把用不上的扩展的 `auto_update` 改成 `false`；
   - 或看 `config.yaml` 里的 `extensions.auto_update`。

   本扩展自己是 `"auto_update": false`，不会更新自己把你正在生成的回复刷掉。

## 技术实现（给想改的人）

| 环节 | 做法 |
| --- | --- |
| 开始记录 | `GENERATION_STARTED`，记下 `chatId`、聊天长度、锚点消息指纹（FNV-1a hash + 前 60 字） |
| 保存内容 | `STREAM_TOKEN_RECEIVED` 给的是**当前累计的原始文本**，直接覆盖写入，节流 800ms 落盘 |
| 结束判断 | `GENERATION_STOPPED` / `GENERATION_ENDED`：内容已经进聊天就丢草稿，没进就留下 |
| 恢复校验 | 聊天长度 + 锚点指纹双重校验，避免串到别的聊天或你后来又发了新消息的情况 |
| 接回 | `chat.push()` + `addOneMessage()` + `saveChat()`，不调用生成 |
| 续写 | 写进 `#send_textarea` 再 `generate('normal')`，等价你手打发送；不用 `continue` |
| 拦截刷新 | `beforeunload` + 捕获阶段拦 `.extensions_info` 里会 `location.reload()` 的按钮 |
| 幂等 | 恢复中加锁 + 二次校验草稿是否还存在，双击按钮不会插两条消息 |
| 调试 | 控制台 `GenerationGuardian.snapshots()` / `.scan()` / `.clear()` / `.copy()` |

关键文件：

```
manifest.json   扩展清单（auto_update: false）
index.js        全部逻辑
style.css       样式，含手机端断点
tests/          本地测试沙盒
```

## 发布到 GitHub

推之前先把 `manifest.json` 里两行改成你自己的（`homePage` 留空也行，填上会在扩展列表里显示作者链接）：

```json
"author": "你的 GitHub 用户名",
"homePage": "https://github.com/你的用户名/st-generation-guardian"
```

然后在本文件夹里执行（本地仓库已经初始化好、已有提交，只要加远端再推）：

```bash
git remote add origin https://github.com/<你的用户名>/st-generation-guardian.git
git push -u origin main
```

发版打 tag（安装时可以直接指定分支或 tag）：

```bash
git tag -a v1.1.0 -m "v1.1.0"
git push origin v1.1.0
```

没配过 git 身份的话，先在仓库里设一次（只影响这个仓库）：

```bash
git config user.name "你的名字"
git config user.email "你的邮箱"
```

## 已知限制

- 关闭流式输出时没有中间内容可存。
- 打断那一次请求的钱回不来，本扩展只保住已经生成的文字。
- 「换一条 / swipe」「替我说话 / impersonate」无法续写，只能进输入框。
- 草稿存在本机浏览器 localStorage：PC 和手机不互通，换浏览器 / 清缓存会丢，内容为明文。
- 拦不住 SillyTavern 在别处直接调用的 `location.reload()`（比如你在别的地方触发了重载），那种情况只能靠草稿恢复。
- 手机端部分浏览器（尤其 iOS Safari）对生成中的刷新确认框支持不佳，可能不弹窗直接刷新 —— 靠草稿恢复兜住。
- 依赖 `STREAM_TOKEN_RECEIVED` 事件，低于 1.12 的旧版本可能没有。
